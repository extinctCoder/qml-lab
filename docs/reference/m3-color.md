# Material 3: color

Source: Google's Material Web repository (`material-components/material-web`),
`docs/theming/color.md`, plus Material 3's color-role guidance. Rewritten in
plain words for our QML design system.

## In one sentence

Components never ask for a color like "green"; they ask for a **role** like
"primary", and the theme (for us: the wallpaper, through matugen) decides
which actual color fills each role.

## How a scheme is made

Five **key colors** (primary, secondary, tertiary, neutral, neutral variant)
are generated from one source color (for us: the wallpaper). Each role below
is a specific shade of one of them, chosen so that every role and its `on…`
partner have readable contrast.

## The roles, and what each is for

**Accents** (color that means something)

| Role | Use it for |
|---|---|
| `primary` / `onPrimary` | key components and **active states**: the main button, the selected thing. Not every component should use it. |
| `primaryContainer` / `onPrimaryContainer` | a softer fill for highlighted states, like a toggle that is on |
| `secondary` / `secondaryContainer` (+ `on…`) | less prominent accents: filter chips, the tonal button |
| `tertiary` / `tertiaryContainer` (+ `on…`) | a contrasting accent, used sparingly |
| `error` / `errorContainer` (+ `on…`) | errors and destructive actions only |

**Neutrals** (structure: most of the screen)

| Role | Use it for |
|---|---|
| `surface`, `background` | the base everything sits on |
| `surfaceContainerLowest` … `surfaceContainerHighest` (5 levels) | layers: panels, cards, popups. Higher = more prominent. |
| `surfaceDim`, `surfaceBright` | the darkest and brightest base surfaces |
| `onSurface` | main text and icons (high emphasis) |
| `onSurfaceVariant` | secondary text and icons (lower emphasis) |
| `outline` | important boundaries: outlined buttons, text fields |
| `outlineVariant` | quiet boundaries: dividers, card borders |

Rule from Material 3: **content on any surface uses `onSurface` or
`onSurfaceVariant`.**

## In our QML

A `Colors` singleton with these role names, generated by a matugen template
(matugen already computes every one of them from the wallpaper). Components
write `Colors.primary`, `Colors.onSurfaceVariant`…, never a hex value.
